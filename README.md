# FC온라인 내 전적 대시보드

넥슨 오픈 API로 내 경기 기록을 받아 `out/dashboard.html` 한 파일로 만든다. 외부 라이브러리는 없고 Node 18 이상만 있으면 된다.

## 처음 한 번
1. https://openapi.nexon.com 에 넥슨 계정으로 로그인한다. 애플리케이션을 등록하면서 게임은 FC온라인을 고르면 **개발 단계 API 키**가 나온다.
2. `.env.example` 을 복사해 `.env` 로 이름을 바꾸고 `NEXON_API_KEY`, `FC_NICKNAME` 을 채운다.

## 기록 받기 · 갱신
```
node fetch.mjs
```
- 계정 정보와 모드별 최근 경기 목록을 받고, **아직 안 받은 경기 상세만** `data/raw/` 에 저장한다. 그다음 `out/dashboard.html` 을 다시 만든다.
- 개발 키 한도는 초당 5회, 하루 1,000회다. 이 스크립트는 한 번 실행할 때 900회까지만 쓰고, 처음 300경기를 받으면 거의 다 쓴다. 한도에 걸려 멈추면 다음 날 다시 실행하면 이어서 받는다.
- 넥슨 데이터는 매시 정각에 약 2시간 전 경기까지 반영된다. 방금 한 경기는 아직 안 나올 수 있다.
- 넥슨 규정상 API로 받은 데이터는 30일 안에 갱신해야 하니, 가끔 다시 실행한다.

## 화면의 새로고침 버튼
- 대시보드 오른쪽 위 **새로고침**을 누르면 브라우저가 넥슨 API를 직접 불러 새 경기만 추가한다. 넥슨이 다른 사이트에서 오는 호출을 허용하고, 로컬 파일로 열어도 된다.
- 처음 누를 때 API 키를 묻는다. 키는 그 기기 브라우저(localStorage)에만 저장되고 HTML 파일에는 들어가지 않는다.
- 버튼으로 받은 경기도 그 브라우저에만 쌓인다. 원본까지 `data/` 에 남기려면 가끔 `node fetch.mjs` 를 실행한다. 겹치는 경기는 자동으로 하나로 합쳐진다.

## GitHub Pages 자동 배포
- `.github/workflows/pages.yml` 이 4시간마다(또는 main에 푸시할 때, Actions 탭에서 직접 실행할 때) 새 경기를 받아 페이지를 다시 배포한다.
- 저장소 Secret `NEXON_API_KEY` 가 필요하다. 키는 로그와 페이지에 나오지 않는다.
- 원본 데이터(`data/`)는 저장소에 올리지 않고 Actions 캐시에만 둔다. 캐시가 비면 다음 실행이 다시 받는다(약 400회 호출).
- 공개 저장소의 예약 실행은 저장소에 60일 동안 활동이 없으면 GitHub가 멈춘다. 멈추면 Actions 탭에서 다시 켠다.

## 미리보기 (API 키 없이)
```
node mock.mjs   →  out/dashboard-mock.html
```

## 파일
| 파일 | 역할 |
|---|---|
| `fetch.mjs` | API 호출과 캐시. 호출 간격·한도를 관리 |
| `compact.js` | 경기 한 판을 대시보드용으로 줄이는 함수. 빌드와 브라우저 새로고침이 같이 씀 |
| `build.mjs` | 원본 JSON을 요약해 `template.html` 에 넣음 (`node build.mjs` 로 빌드만 따로 할 수 있음) |
| `template.html` | 대시보드 화면 (야간 경기 전광판 디자인, SVG 차트, 모바일 대응) |
| `PRODUCT.md`, `DESIGN.md` | 누가 왜 쓰는지 / 디자인 규칙 — 화면을 고칠 때 기준 |
| `mock.mjs` | API 응답과 같은 모양의 가상 데이터 |

## 실제 데이터로 확인된 것
- 슛 좌표 `x, y` 는 0~1, x=1 이 상대 골문(골라인 위 슛은 1.01 정도).
- `matchDetail.averageRating` 은 4 안팎이라 선수 평점과 기준이 달라 쓰지 않고, 출전 선수 평점 평균을 쓴다.
- 시즌 메타 `seasonid.json` 은 2026-11-19 이후 없어지고 `class.json` 으로 바뀐다. 둘 다 받아서 `class` 를 먼저 쓴다.
